# 수용기준과 검증 계획

버전 0.1 / 2026-10-16. **[제안] 향후 제품 구현의 수용시험**이다. 이 PR은 문서만 작성했으며 아래 제품 시험을 실행하거나 통과한 상태가 아니다. 이번 문서 검증 결과는 [저장소 확인 기록](REPOSITORY_STATUS.md)에 별도로 기록한다.

## 1. 검증 원칙

- 사용자 핵심 흐름을 기준으로 UI → 중앙 명령 → 실행기 → 결과/승인 → 실제 상태까지 확인한다.
- 화면 스크린샷, 요청·응답의 비밀 제거본, task/run/action ID, 이벤트·외부 영수증을 함께 남긴다.
- 외부 쓰기는 테스트 계정·플랫폼이 제공하는 테스트 환경을 먼저 사용한다. 실제 계정 게시·발송·예산 변경은 구체 action에 대한 명시적 승인이 있을 때만 검증한다.
- 연결 미지원·결과 불명·사용량 미보고는 그 상태대로 통과 조건을 정의한다. 거짓 성공·0원·자동 재실행으로 보정하지 않는다.
- 숫자 기준·성능 환경·시간대는 구현 전 운영자가 확정한다. 고정된 시험 데이터와 부하를 기록해 재현 가능하게 한다.

## 3. 종단 간 필수 여정

**E2E-A / M2 완료 관문**

1. 검증된 가상 SKU·원본·상품 사실을 등록한다.
2. iPhone 웹에서 집중 항목·마감·우선순위를 정하고 착용샷/상세 초안을 지시한다.
3. Mac offline 대기 → 재연결 → 단일 claim → 실행 시작을 관측한다.
4. 실행 도중 단절·결과 ACK 유실을 주입하고 같은 run 결과가 복구되는지 확인한다.
5. 원본/결과 비교 후 수정요청 → 새 버전 검수 승인, 다음 AI에 SNS 초안 인계한다.
6. 홈·SKU·채널·실행기록에서 상태·다음 행동·승인본이 같은 task에 연결되는지 확인한다.
7. 실제 게시 없이 초안·승인본·수동 전달 경로까지 종료한다. 외부 자동 실행은 지원하지 않는다고 표시한다.

**E2E-B / M3 선택 서비스 출시 관문**

검수 승인본 선택 → 정확한 계정·본문·비용/일정 검토 → 외부 action 승인 → 실행 → 외부 영수증 조회 → 결과 URL/지표 연결을 확인한다. 별도 시도에서 승인 후 payload 변경·중복 탭·네트워크 응답 유실·승인 철회를 주입하고 무승인·중복 외부 실행이 없는지 검증한다.
