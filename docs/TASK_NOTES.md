# 작업별 공유 노트

## 구현 범위

기존 작업대장의 고유 task_id와 연결한 독립 블록 편집기다. 사용자 제공 MakerNote 계열 레퍼런스의 기능 설명을 참고했으며, 재사용 허가가 확인되지 않은 원본 HTML/JavaScript/CSS를 복사하거나 가져오지 않았다. 추가 외부 라이브러리도 없다. 원본 파일과의 호환성이나 기능 전체 복제를 주장하지 않는다.

- 작업대장 각 행의 `작업 노트 열기` → `/notes?task=TASK_ID`.
- 문단·제목·체크리스트·표. 문단에 `/`를 입력해 메뉴를 열고 키보드/버튼으로 블록 종류를 선택한다. 위/아래 이동·삭제와 문단 추가를 제공한다.
- 새 노트·하위 페이지, 같은 작업 안의 제목/내용 검색. 페이지 ID와 상위 페이지 ID는 VPS에서 보존한다.
- 수정 후 800ms 자동 저장. 성공 시 VPS revision을 표시한다. 실패/경합과 현재 탭에만 있는 입력을 분명히 구분한다.
- 기존 디자인·작업 상태/우선순위/승인/완료 기준은 그대로다. 노트는 실제 AI 실행이나 작업 완료 처리가 아니다.

제한: 작업별 최대 100페이지, 하위 8단계, 페이지당 200블록, 표 30행×6열. 이미지 업로드·실시간 공동 커서·리치텍스트/파일 호환·실행 명령은 포함하지 않는다.

## VPS 저장과 인증 경계

공유 원본은 기존 VPS SQLite다. `note_pages`는 최신 제목/블록/revision/갱신 시각을, `note_commands`는 멱등 저장 영수증을 보관한다. 인증된 기존 SSH localhost 경로 뒤의 API를 사용한다. 앱은 loopback에만 바인딩하고 Host/Origin/JSON 경계를 유지한다. 개인 노트를 인증 없이 인터넷에 공개하는 기능은 아니다. 외부 HTTPS 주소/새 인증은 별도 승인·검증 작업이다.

localStorage를 공유 원본이나 임시 대체 저장소로 사용하지 않는다. 저장 실패 중 입력은 현재 탭 메모리에 남고 이탈 경고를 제공한다. 탭이 닫히기 전에 저장을 재시도하거나 초안 표시 영역의 내용을 복사해야 한다. 저장된 노트는 다른 연결/재접속에서 VPS로부터 복원한다. 서버 저장 성공 전의 입력이 모든 기기에 동기화됐다고 표시하지 않는다.

## 실패와 충돌

진행 중인 저장 요청은 payload/멱등 키를 고정한다. 응답이 불확실하면 같은 요청으로 재확인하고, 그 사이 추가로 입력한 내용은 성공 후 다음 revision으로 이어서 저장한다. 네트워크 실패는 제한된 지수 대기로 재시도하고 온라인 복귀나 `저장 다시 시도`로 재확인한다.

다른 클라이언트가 먼저 저장하면 409로 멈춘다. 자동 덮어쓰기/재기준화를 하지 않으며 내 입력을 보존한다. `내 입력 임시 보관본`을 확인하고, 명시적으로 서버본을 열면 이전 초안을 탭 내 읽기 영역에 남긴다. 서버본을 기준으로 필요한 부분을 다시 편집할 수 있다. 페이지를 바꾸기 전에 저장 상태를 확인하며, 새 페이지를 읽는 중에는 기존 편집 입력을 비활성화한다.

## API

기존 SSH 권한을 가진 운영자만 호출한다. 새 로그인 권한/키/토큰을 생성하지 않았다.

- `GET /api/notes?task_id=ID&q=검색어`: 작업과 페이지 메타데이터. 블록 전체를 한꺼번에 내려주지 않는다.
- `GET /api/notes/page?page_id=UUID`: 저장된 현재 페이지.
- `POST /api/notes/pages`: `{task_id,title,parent_id,idempotency_key}`. 존재하는 작업에만 생성하며 같은 작업의 상위 페이지를 검사한다.
- `POST /api/notes/save`: `{page_id,expected_revision,title,blocks,idempotency_key}`. 성공 영수증은 `{page_id,revision,updated_at,saved:true}`.

노트 POST 본문은 256KiB 이내이며 다른 API의 기존 16KiB 한도는 유지한다. revision 검사·행 갱신·영수증은 SQLite 단일 쓰기 트랜잭션이다. 다른 작업으로 노트를 이동하거나 작업 원본 필드를 바꾸는 경로는 없다. HTML은 해석하지 않고 텍스트/입력 값으로 표시한다.

## 검증

저장소 테스트는 Unicode/블록 보존·다른 작업 불변·요청 중복/ID 충돌·동시 편집 단일 승자·잘못된 표/체크·다른 작업의 상위 페이지 차단을 확인한다. 실제 HTTP의 새 연결과 서버 재시작 후 저장된 내용 복원, stale revision 409, 기존 Origin/본문 한도를 검증한다.

실제 브라우저의 가상 작업에서 슬래시 메뉴→제목/체크/표, 하위 페이지, 검색, 자동 저장, 탭에만 한정한 저장 통신 장애 후 입력 보존/재시도, 두 번째 실제 HTTP 클라이언트와의 충돌, 명시적인 서버 복구/재접속을 검증했다. 가상 검증 노트는 실제 업무와 분리한다. 개인 자료·캡처·DB는 공개 Git에 넣지 않는다.

최종 로컬 검증: Python 42개·Node 16개 통과. 1440×1000/390×844 화면에서 대비·가로 넘침을 확인했고, 체크박스는 시각 크기 24px와 별개로 네이티브 label의 44×44px 클릭 영역 및 동작을 확인했다. 독립 마무리 검수는 `ship`, 디자인 문서 검수는 기존 시스템 유지(`No changes`)다. 운영 배포 여부와 외부 HTTPS 상태는 별도 운영 기록으로 구분한다.
