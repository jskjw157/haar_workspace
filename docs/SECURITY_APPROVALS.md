# 보안·승인·로그인 계획

버전 0.1 / 2026-10-16. **[확정]** 사용자 요구와 **[제안]** 구현 전 설계를 구분한다. 이 문서는 보안 기능이 이미 구현·검증되었다는 인증이 아니다. 관련 문서: [PRD](PRD.md), [adapter 계약](ADAPTER_CONTRACT.md).

## 1. 승인 종류와 범위

**[확정]** 초기에는 작업 기록·검토·지시를 우선한다. 실제 게시, 광고 예산 변경, CS 발송은 명확한 승인 기반이다. 실행 완료와 결과 검수 승인은 분리한다.

| 구분 | 예 | 허용 결과 | 허용하지 않는 것 |
| --- | --- | --- | --- |
| 작업 지시 | 사진 원본으로 초안 생성 | 정해진 파일 범위 안의 초안 생성 run | SNS 게시·추가 구매·CS 발송 |
| 결과 검수 | 착용샷 v2의 제품 형태·색상 확인 | 해당 artifact 버전을 승인본으로 지정 | 해당 이미지를 외부 계정에 게시 |
| 외부 행동 승인 | 지정 계정에 캡션·영상 게시 | 고정된 action의 범위·유효기간 안에서 한 번 실행 | 다른 계정·본문·파일·예약시간으로 실행 |
| 정책·권한 승인 | 특정 스킬의 새 권한·버전 적용 | 지정 범위의 다음 run부터 적용 | 모든 AI/기기에 영구 전체 권한 부여 |

이모지·댓글·채팅의 “좋아”는 외부 행동 승인 토큰으로 해석하지 않는다. 결과 승인 버튼과 ‘게시 승인’ 버튼은 별도다. M1/M2에서는 실게시 연결이 없어도 승인본·수동 실행 결과 URL을 기록할 수 있다. 수동 실행은 `execution_mode=manual`과 사용자 확인·외부 증거를 남기며 자동 adapter 검증과 구별한다.

## 2. 외부 행동 승인 계약 [제안]

승인 요청에는 다음을 변경 불가능한 스냅샷으로 묶는다.

- `action_id`, `task_id`, 대상 서비스·계정·리소스·행동 종류.
- 본문·미디어 artifact_version_id·내용 digest·변경 diff·첨부.
- 예약 실행 시각·시간대·허용 실행 창, 광고라면 통화·기존/변경 금액·단위(일/총액)·기간·상한.
- 대상 고객 또는 댓글/문의 ID, 발송 채널. 민감정보는 권한 있는 승인 화면에 필요한 최소치만 표시.
- 승인 요청자, 실제 승인자, 결정 시각·만료 시각, 정책 버전, 취소·복구 가능 범위.

`payload_digest`는 대상·버전·비용·시간·범위를 포함한 정규화 데이터로 계산한다. 승인 레코드는 digest에 묶고, 실행 도구는 실제 payload에서 다시 계산한다. 승인 이후 한 필드라도 달라지면 다시 승인받는다. 운영자가 명시적으로 취소하거나 만료되면 실행하지 않는다.

승인 상태는 `pending → approved/rejected/expired/revoked`로 관리한다. 승인 소비와 action 실행 예약은 원자적으로 기록한다. 소비 후 망이 끊겨도 새 승인으로 다시 쓰기를 실행하지 않고 기존 action 영수증부터 조회한다. 같은 승인 버튼을 두 번 눌러도 동일한 결정을 반환하며 다른 action으로 사용할 수 없다.

기본 만료시간·예약 허용 창·금액 한도는 미결정이다. M3 진입 전에 운영자가 확정한다. UI는 결정을 생략한 채 무기한 승인으로 보정하지 않는다.

## 3. 권한을 강제할 위치

| 경계 | 강제할 내용 |
| --- | --- |
| 웹/API 인증 | 사용자 식별·세션·workspace 접근·CSRF/재전송 방지·승인 권한 |
| Task Core | 단일 상태 쓰기, revision·소유권, 승인 행위자 확인 |
| 채널 bridge | 출처 서명/인증, 허용 채널·사용자 매핑, 메시지 중복·과거 이벤트 재생 검사 |
| 실행 gateway | 실제 capability·스킬 버전·허용 도구·lease 세대·최신 revoke 확인 |
| 기기 adapter | 허용 루트·프로세스·파일 접근·최소 권한·기기 journal |
| 외부 쓰기 도구 | action digest·승인·기한·단일 소비·예산·대상 검증 후만 실행 |

모델의 “승인을 받겠다”는 답변은 강제 경계가 아니다. 외부 쓰기 권한이 있는 shell·브라우저·MCP가 승인 도구를 우회할 수 있다면 그 run에는 해당 권한을 제공하지 않는다. 격리·승인 경계가 검증되지 않은 런타임은 초안 생성까지 허용한다. 임의 웹페이지·공급처 자료·고객 메시지·AI 출력은 명령이 아닌 데이터로 취급하며 권한을 넓히는 근거가 될 수 없다.

Mac의 일반 사용자 권한으로 실행하는 CLI는 파일·프로세스 접근 범위가 넓을 수 있다. 강한 경계는 OS 계정·sandbox·컨테이너 또는 동등한 도구 권한 격리로 검증해야 한다. 특정 격리 기술은 미결정이며 Argo의 안내 문구나 UI 승인만으로 이 한계를 해결했다고 주장하지 않는다.

## 4. 상품 사실·이미지 정확성

**[확정]** 임의로 추정하거나 확인되지 않은 제품 스펙을 게시하지 않는다.

**[제안]** 사실은 `unknown / sourced / verified / disputed / outdated`로 분리하고, 게시용 필드는 `verified`인 근거·수정일·적용 SKU/변형을 가진 값만 허용한다. 모델이 자료에서 추출한 사실은 `sourced` 후보로 시작한다. 확인되지 않은 소재·치수·효능·원산지·인증을 단정하는 문장을 게시 action에서 차단한다.

이미지 검수에는 원본 대비 형태·길이·단추·주머니·무늬·액세서리·색상·착용 맥락을 확인한다. 원본에서 알 수 없는 디테일을 AI가 생성한 경우 실제 제품 사실로 확정하지 않는다. 영상 자막·캡션도 같은 스펙 검사를 받는다. 법적 표현·광고 심의 등 상품별 추가 기준은 별도 확인 항목이며 이 문서가 이를 대신하지 않는다.

승인본은 안정적인 파일 버전/복사본과 digest 등으로 고정해야 한다. Drive URL이 같아도 파일 내용은 바뀔 수 있다. 고정·재검증이 불가능하면 자동 게시 기능을 열지 않는다. 실행 직전 digest가 달라지면 승인을 무효화한다.

## 5. 비밀정보와 로그인

**[확정]** 암호·토큰 원문을 중앙 DB·모델 입력·로그에 저장하지 않는다. 별도 Mac Keychain helper를 계획한다. 기존 Apple Passwords의 모든 계정을 자동 열람·이관할 수 있다고 가정하지 않는다. 비밀 CSV 이관은 사용자 직접 또는 별도 명시적 승인 대상으로 두며 이번 작업에서는 읽거나 옮기지 않는다.

**[제안 계획]** 구현 전 Apple 공식 API·서명·entitlement·배포 방법과 사용자 인증 UX를 검증한 뒤 다음 경로를 설계한다.

1. 운영자가 로컬 helper에서 필요한 서비스 연결을 새로 등록하거나 서비스 공식 로그인 흐름을 진행한다.
2. helper는 앱 전용 항목을 macOS Keychain 등 검증된 로컬 보관소에 저장한다. 필요한 항목만 선택하며 기존 Apple Passwords 자동 접근을 전제하지 않는다.
3. 중앙에는 비밀이 아닌 `connection_ref`, 서비스·계정 표시명, 허용 행동, 기기 ID, 연결 상태·만료 여부만 보낸다.
4. 실제 외부 요청은 로컬의 제한된 credential broker/실행 도구가 수행한다. 모델에 비밀 값을 반환하지 않고 필요한 결과·영수증만 반환한다.
5. 연결 해제·기기 분실·권한 철회 시 중앙의 실행 권한과 로컬 연결을 각각 폐기하고 결과를 기록한다.

실행기가 비밀을 환경변수로 받는 경우에도 모델이 shell로 환경을 읽을 수 있으면 노출 방지가 성립하지 않는다. credential을 가진 broker와 AI 프로세스의 권한을 분리하고, 임의 환경·파일 읽기를 허용하지 않는 경계를 검증해야 한다. 로컬 CLI 자체 로그인 저장소는 해당 도구의 로컬 경계에 남기고 중앙으로 복사하지 않는다.

중앙–adapter 인증에는 공개키·challenge 서명과 짧은 세션을 사용하는 방식을 후보로 둔다. 중앙 영구 저장소에는 검증용 공개키·폐기 상태 등 비밀이 아닌 정보만 두고 bearer token·refresh token 원문은 저장하지 않는다. 전송 헤더·쿠키도 로그에서 제외한다. 웹 로그인 방식과 계정 복구는 아직 미결정이며 서비스 OAuth 토큰의 중앙 보관을 요구하는 방식은 확정 요구와 충돌하므로 그대로 채택하지 않는다.

## 6. 데이터 최소화·공개 저장소

이 저장소는 2026-10-16 확인 시 공개 상태다. 문서에는 설계와 가상 식별자만 넣고 실제 고객 데이터, 원본 사진, 내부 Drive URL, 공급처 계약·손익 원문, 서버 접속 주소·credential을 넣지 않는다. 저장소 visibility를 임의 변경하지 않는다.

앱은 인증된 workspace 안에서 SKU 참조·작업·승인 이력을 보관한다. Drive 링크는 권한 자체가 아니며 ‘링크가 있으면 누구나 보기’를 기본으로 만들지 않는다. 계정/고객 참조를 필요 이상 로그에 남기지 않는다. 원본 접근 권한을 확인할 수 없으면 미리보기와 승인을 중단한다.

보존기간은 미결정이다. **[제안]** 운영 전 작업·감사·고객정보·파일별 보존기간·삭제권한·백업 만료를 정하고 고객정보는 최소화·가명 참조한다. 분석/텔레메트리로 원문을 외부에 전송하지 않는다. Paperclip 같은 의존성의 기본 텔레메트리·로그·동기화도 고정 버전 설정과 전송 필드를 검토해야 한다.

## 7. 감사·사고·복구

감사 레코드는 행위자, 종류, 대상 ID·버전·digest, 정책·스킬·지침 버전, 승인 결정, 실행 영수증, 변경 시각·인과 관계를 담는다. 업무용 원문과 최소 메타데이터를 분리하고 접근 권한을 다르게 한다. 비밀 값은 저장 후 마스킹이 아니라 수집/출력 전에 제외한다.

의심 행동은 새 외부 실행을 정지하고 해당 adapter·연결·스킬 버전을 철회한다. 실행 중 프로세스 중단과 외부 효과 여부를 조회해 `unknown`을 숨기지 않는다. credential이 노출되면 로컬에서 폐기·재로그인하고 중앙에는 사건 참조·복구 상태만 기록한다. 감사·멱등성 기록을 삭제해 문제를 숨기거나 중복 실행을 허용하지 않는다.

출시 관문은 [수용기준 AC-13~19, 22](ACCEPTANCE_CRITERIA.md)다. 제품이 아직 구현되지 않았으므로 현 시점에는 실행 차단·비밀 유출 방지·격리의 통과 증거가 없다.
