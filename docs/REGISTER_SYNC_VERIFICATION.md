# 작업대장 연결 검증 기록

검증일: 2026-10-18. 기능 커밋: `563af4da3d2f76c09e254b468c4f37752c6ed14b`.

## 확인한 결과

- 공식 Library materialization으로 JSON·MD의 보관 버전 7을 각각 확인했다. JSON의 문서 내부 버전 1과 Library 보관 버전 7은 서로 다른 값으로 보존한다.
- 실제 원본은 28건이며 고유 ID·기존 번호·완료 기준·근거·블로커·사용자 우선순위·알려지지 않은 확장 필드가 전체 JSON 비교에서 유지됐다. 실제 작업 내용과 파일은 공개 Git에 포함하지 않았다.
- 로컬 격리 DB에서 과거 확인본 19건 → 27건 → 최신 28건 import를 확인했다. 이력과 이전 확인본을 보존하고, 다운그레이드·같은 버전의 다른 내용·원본 바꿔치기·기존 작업 삭제·동시 수정 충돌을 거부한다.
- Python 27개 테스트, 기존 화면 상태 테스트 6개, 작업대장 화면 테스트 4개 통과. 임시 HTTP 서버에서 import → 변경 제안 → export → 실제 새 확인본 import → 확인 이력이 API에 나타나는 흐름을 검증했다. 테스트는 격리 DB를 사용하며 실제 Library 원본을 쓰지 않았다.
- 동일한 Orca 탭 하나에서 1440×1000·390×844 두 화면을 검사했다. 28건, 가로 넘침 없음, 계산된 텍스트 대비 위반 없음. 모바일 첫 화면에 작업 ID·제목·상태가 보인다. 원본 ID·전체 해시·Library/문서 버전은 연결 정보에서 확인한다.
- 독립 마감 검토 `ship`, 디자인 문서 검토 `No changes`. 기존 공통 스타일·홈 기능 JavaScript·8개 이미지·백업 스크립트는 이전 배포 코드와 동일하다. 중단된 사진 디자인 변경은 별도 체크아웃에 보존했다.

실제 원본·화면·원문 로그·로컬 DB 및 검토 상세는 무시된 로컬 `output/register-sync/`와 저장소 밖 입력 폴더에 보관한다.

## 운영 반영 상태

**사용자 운영 승인 후 배포·운영 import를 완료했다.** 운영 기능 커밋은 `563af4da3d2f76c09e254b468c4f37752c6ed14b`이며, 기존 SSH 터널에서 [중앙 작업대장](http://127.0.0.1:3311/register)에 접속한다. 이 주소는 터널이 있는 Mac의 로컬 주소이며 iPhone/외부 공개 주소가 아니다. 기존 [홈](http://127.0.0.1:3311/) 상단·하단의 중앙 작업대장 링크에서도 접근한다.

- 원격 HAAR 단일 서비스만 중지·재시작했다. 현재 코드 포인터는 기능 커밋 릴리스이고 서비스는 active/running, 자동 재시작 횟수 0이다.
- Library v7·28건 전체 JSON이 로컬 원본과 운영 API에서 일치한다. 고유 ID별 상태 28건과 사용자 확정 최우선 2개가 실제 운영 화면에서 API와 일치했다. 원본 상태와 실제 작업 실행은 별개다.
- 운영 health: `status=ok`, `mode=intake_only`, `dispatch_enabled=false`. 새 Library 상시 수집·실행 권한은 추가하지 않았다.
- 일관 백업 3개를 새 파일로 보존했다: 최초 배포 전 백업, import CLI의 추가 백업, 재시작 재개 전 확인본 포함 백업. 모두 무결성 검사 통과. 이전 코드 릴리스도 보존했다.
- 기존 records 3건·focus 1건·commands 4건·events 4건 및 해당 테이블/인덱스 스키마·user_version을 함께 비교한 해시는 배포 전후 동일하다. 작업대장 테이블은 별도 추가됐으며 import는 1회다. DB를 복원하거나 덮어쓰지 않았다.
- 서비스 unit 파일과 DynamicUser/ProtectSystem/ProtectHome/StateDirectory/MemoryMax 128MiB/TasksMax 32 설정은 그대로다. 다른 서비스·인증·방화벽·사진 디자인은 변경하지 않았다.
- 기존 3311 터널을 통한 HTML/JS/CSS 바이트 대조와 실제 1440×1000·390×844 운영 캡처를 확인했다. 28개 행의 상태가 원본/API와 일치하고 가로 넘침·텍스트 대비 위반이 없으며 모바일 첫 화면에 첫 작업이 보인다. 전용 검증 탭은 확인 후 닫았다.

초기 자동 승인 거절은 사용자 운영 승인으로 해소됐다. 승인 후 첫 배포는 백업·import 뒤 WAL 파일 보호 검사에서 멈춰 기존 코드로 복구했다. 격리 재현에서 읽기 전용 SQLite 검사가 빈 WAL을 남길 수 있음을 확인했다. 재개할 때 읽기 연결을 명시적으로 닫고, 서비스 정지 상태에서 SQLite의 정상 체크포인트를 완료한 뒤 코드 포인터를 교체했다. WAL을 수동 삭제하거나 import를 반복하지 않았다. 최종 운영 DB 소유권/모드와 정상 조회를 다시 확인했다.

원문 배포 영수증·API별 상태 대조·운영 캡처는 로컬 `output/register-sync/`에 보관하며 공개 Git에는 실제 작업 내용/원본을 넣지 않는다.

## 남은 연결 경계

화면의 60초 조회는 VPS 확인본만 갱신한다. Library 상시 수집·자동 양방향 반영과 각 AI의 실제 실행 수집은 미연결이다. 변경 제안의 JSON/MD 후보는 권한 있는 소비자가 최신 원본 버전과 충돌을 검사해 반영하고, 다시 import한 뒤에만 확인된다. 새 인증·OAuth·지속 권한·방화벽 변경은 추가하지 않았다. 원본에 근거가 없는 작업 1건은 미기록 경고로 남긴다.
