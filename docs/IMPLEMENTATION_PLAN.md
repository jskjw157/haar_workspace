버전 0.1 / 2026-10-16. **[제안] 향후 구현 준비 계획**이다. 현재 승인된 범위는 문서 작성·읽기 전용 코드 조사·같은 Draft PR의 검토용 게시다. 앱 구현·서버 설치/변경·배포·PR 병합을 시작하지 않는다. 아래 작업·시험·수치는 완료 실적이 아니다.

## 4. 검증 층과 증거

| 층 | 시험할 것 | 예시 증거 |
| --- | --- | --- |
| 정적 문서·schema | R→설계→AC 연결, enum/revision·권한 일관성, 예시 JSON·링크 | 문서 diff·validator 결과. 이번 PR이 수행하는 층 |
| 계약/상태 | 중복 키·다른 payload·stale revision·단일 claim·lease·승인 digest·순서/버전 | 정상/부정 fixture, 원장/확장 변경 비교 |
| 통합 | Paperclip 배정→checkout→queue/run/event, Buzz route mapping, 권한/복구 hold | task/run/action ID와 비밀 제거된 요청·이벤트 |
| 장애 주입 | offline·ACK 유실·재시작·terminal 늦은 이벤트·취소 경합·DB 반영 지연 | 실행 횟수·journal/receipt·cursor, unknown이 재실행되지 않는 증거 |
| 실제 사용자 여정 | iPhone과 Mac의 집중→지시→검토→인계, 선택 서비스 외부 승인 | S 화면 전환·핵심 조작·미리보기/버전·E2E-A/B |
| 자원/운영 | ADR의 idle/일상/동시/재연결 burst와 backup/upgrade | 환경·표본·peak·상한·오류·복구 시간. 미측정은 그대로 표시 |

시험 데이터는 가상 SKU·가짜 credential canary·권한이 분리된 테스트 계정·고정 파일 버전을 사용한다. 실제 고객/계정·상품 파일·비밀을 공개 PR 증거에 넣지 않는다. 결과마다 버전·환경·시각·입력·예상/관측·담당·미통과/미실행을 기록한다. 앱 구현 전에는 제품 AC를 통과로 체크하지 않는다.

각 작업의 완료 정의는 ① 합의된 범위 동작, ② 해당 AC의 긍정/부정 증거, ③ 실제 원장/노드/외부 상태 일치, ④ 미확인 capability·운영 한계 명시, ⑤ 고지·업데이트/복구 영향 확인이다. 문서 세트 완료는 이 중 문서 정합성만 검증하며 제품 출시 완료와 다르다.

## 5. 사용자와 의논할 선택과 결정 기록

선택지의 상세는 [화면설계 UX-01~05](USER_JOURNEYS_SCREENS.md#5-사용자와-논의할-화면-선택지), [TDD TECH-01~05](TDD.md#7-통합업그레이드와-논의할-선택) 한곳에 둔다. 먼저 의논할 것은 다음과 같다.

1. 홈에서 집중 3개와 승인 대기 중 무엇을 먼저 펼칠지, 모바일 메뉴에 대화를 고정할지.
2. 지시할 때 SKU/목표와 AI 중 무엇을 먼저 선택할지, 결과 비교를 어떻게 볼지.
3. 사용자 확인 VPS Hermes·OpenClaw의 설치/API, COKACDIR의 정확한 버전·세션 연동 API, Orca 제품명·GPT 호출 방식과 첫 직접 실행 대상.
4. Paperclip 지원 확장과 최소 patch, Buzz 재사용 단위 중 어떤 증거로 선택할지.
5. 측정 예산을 충족하는 기존 런타임과 경량 Rust adapter 대안, Mac 연결 운송 방식.

확정된 제품 요구를 다시 선택지로 열지 않는다. 예를 들어 집중 최대 3개, 미확인 스펙 게시 금지, 사람의 외부 승인, 비밀 중앙 저장 금지는 유지한다. 선택의 기본 상태는 ‘제안/검토 대기’이며 아직 사용자가 채택한 것으로 표시하지 않는다.

결정 기록에는 decision_id, 관련 R/UX/TECH/V/ADR ID, 대안·권고·근거, 사용자 선택·시각·적용 범위, 영향받는 문서/AC, 후속 검증 담당을 남긴다. 사용자가 범위/설계 선택을 승인해도 구현·배포·병합 승인을 묶어서 추정하지 않는다.
